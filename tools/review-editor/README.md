# RhythmHint Studio

本地四轨排键编辑器。双击 `index.html`，或打开包含谱面的独立 HTML 即可使用。无需安装前端依赖，不上传谱面和音乐。

## 打开自己的谱面

1. 点击左上角「打开谱面」，直接选择 `.adofai` 原谱，也可以将文件拖进页面。支持的关卡会立即生成排键，不需要命令行或先转换格式。
2. 点击「载入音乐」单独选择关卡目录中的音乐文件。浏览器不会根据谱面里的文件名自动读取旁边的歌曲。
3. 在轨道上调整后，点击「导出审核」保存 `.review.json`。下次选择这个 JSON，即可保留修改继续审核；原始 `.adofai` 不会被改写。

直接打开 `.adofai` 使用有限范围的离线解析：支持 `angleData` 和常见 `pathData`，砖块上的 `SetSpeed` / `Twirl` / `Pause`，以及视觉重复、条件特效、半径变化等表现事件。Pause 包含游戏版本 9–16 的兼容迁移；旧版 pathData 支持绝对方向与中旋，现代版本也支持相对方向。界面会标注「离线近似」，因为它不是游戏实际 `entryTime`。

含 `Hold`、`MultiPlanet`、`AutoPlayTiles`、非零角度偏移变速等尚未支持的时序事件，或旧版 pathData 的内嵌控制字符时，会明确提示原因。此时在新版 Mod 中 **F8 → 状态 → 导出当前关卡排键**，再用「打开谱面」选择导出的 JSON。复杂关卡及正式总结规则优先使用此方式。

## 在谱面上操作

- **滚轮**连续浏览，**Ctrl + 滚轮**以指针位置缩放；左侧整曲概览可点击、拖动快速定位。
- **点击音符**选择，**横向拖动**移到其他轨道。多押可以单独拖动其中一个按键到空轨，并保留该按键的长按时长。支持 1–4 键，四押可用镜像交换各手指的长按。
- 在空白处**拖出选框**选择一组音符，**Shift**点击或框选追加选择。整组可拖动、按 **← / →** 移轨，按 **M** 左右镜像；有任何音符越界就取消整次操作。
- **↑ / ↓**选择时间上的后一个 / 前一个音符，**D F J K**把选中的单押直接放到指定轨道。
- **空格**播放 / 暂停，**Home**回起点，底部可调播放速度。没有音乐也可预览滚动，有音乐时以音频为主时钟。暂停会先停止音频再记录实际位置，普通续播不重新定位；只有拖动时间、改偏移或循环回跳才定位音频。
- 载入本地音乐后显示波形；音频时间 = 谱面时间 + 偏移。设置 **A / B** 可循环试听，修改偏移后请确认循环范围仍在歌曲内。
- 原排键作为灰色虚线显示，修改后的音符为橙色；“原谱影子”可随时关闭。
- 右侧填写选区理由、标记审核。理由可以批量填写；没有修改但认可的原排法也能标记。侧栏可折叠，窄窗口默认折叠。
- **Ctrl Z / Ctrl Shift Z**撤销 / 重做，**Ctrl S**导出完整审核 JSON。页面右上角问号有快捷键说明。

这是用于归纳排键偏好的审核编辑器，原始击打时间、按键数量和长按时长保持不变。它允许任意不重复的四轨组合，包括跨手双押、三押及四押；这些人工选择只进入审核文件，尚未写回游戏。时间网格默认以秒显示；BPM、起拍和细分控制的“节拍网格”是人工设置的辅助网格，不代表已读取关卡的变速事件，也不会量化或吸附改变原时序。

## 保存与继续

无论从 `.adofai` 开始还是导入 Mod 的审核 JSON，修改记录都与原排键分开保存。完整 `.review.json` 可重新导入继续；`.summary.json` 仅为差异摘要，不能替代审核文件。旧版审核文件仍兼容。重新打开 `.adofai` 会重新生成自动排键，想继续已有修改时请打开导出的 `.review.json`，或显式恢复匹配的本机草稿。

本地草稿按谱面标识及原始数据验证。重新打开时显式点击“恢复草稿”；不会静默覆盖导入文件里的审核。文件协议下浏览器存储可能不可用，换路径也可能影响草稿，因此请以导出的审核文件为准。同一谱面不建议同时在多个窗口编辑。

## 算法版本

当前浏览器排键与上游 `054fe9cd6a8961afbf0c8f9c181bd3dcedb12b18` 的核心对齐，算法标识另含 `TimeReset` 或 `ReviewPreferenceV1` 风格。导出保留全部 16 项参数及原始击打角度。未知角度按时间窗分组，已知角度使用角度与相邻间隔阈值；每个合并提示可有 1–4 键。

旧 `NotePlanner/1.0.0` 审核 JSON 仍能打开、修改和导出，原始排键不会被新算法替换。`CompareReviewRules.cs` 只比较当前版本的 TimeReset 基线，旧版本须重新从游戏导出后再做新一轮比较。

## 开发

测试需要 Node.js、.NET 10 SDK 和 Python 3；可用 `DOTNET_HOST_PATH` 和 `PYTHON` 指定可执行文件。整套测试不依赖私人谱面、游戏 DLL 或预先生成的调试文件。planner parity 会现场调用 C# 生成合成数据，逐音对照两种风格、角度与时间阈值、3/4 押、长按、镜像、两手及随机序列，并验证 layout-lab 和实际打包产物使用同一规划器。

```powershell
node --test tools/review-editor/*.test.cjs
node tools/preview-review-editor.cjs
node tools/build-review-editor.cjs Charts/reviews/example.review.json Charts/reviews/example.html
```

预览服务仅监听 `127.0.0.1:18742`，只提供固定的编辑器文件及合成演示，不提供个人谱面、音乐和其他目录。打开对应地址后可在本机选择文件；正式使用仍可直接双击 HTML。

`core.js` 管理文件格式与审核证据；`studio-model.js` 管理坐标、选区和原子批量修改；`studio-audio.js` 管理时钟、音乐、波形及循环；`note-planner.js` 移植 C# 排键规则，`adofai-import.js` 负责受限的原谱解析；`app.js` 连接界面和交互。导入已有审核 JSON 时保留其中的原始排键，不重新计算。
