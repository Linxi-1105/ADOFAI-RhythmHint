# 排键算法与审核边界

当前基线为上游 `054fe9c` 的转角排键实现。默认排法继续使用时间重置法，审核偏好是主动选择的另一种排法。本文描述数据来源和实现边界；使用方式见[审核指南](排键审核指南.md)，可选排法见[审核偏好说明](审核偏好实验规则.md)。

Mod 版本号沿用 main 的维护结果；本次审核工具与可选排法改动不单独修改 `Directory.Build.props` 的版本号。

## 游戏数据到提示音符

`GameReader` 读取游戏已经算好的砖块时间、自动/中旋/假砖标志、长按、速度及转角，交给 `FloorHits.From`。起点不按；自动砖、中旋和假砖不产生独立击打；连续长按合并，长按结束砖不另算按键。

`FloorHits.CheckAngles` 会分别核对砖块转角属于出发段还是到达段，用时长、速度和转角计算匹配比例。不够可信时退回未知角度；已知角度会累计跨过不需要按键的砖。这样得到的 `TileHit.Angle` 是从上一块要按的砖到这一块的转角，不能直接把原始方向值当作它。

`NotePlanner.Plan` 接收该击打序列。它不读取音乐文件或个人审核答案；输出音符时间取合并组的首个击打，砖块范围记录首末边界。范围中可能包含被过滤的砖，不能用整数范围重造原始击打序列，所以审核导出另存完整 `sourceHits`。

## 当前分组与排键

1. **已知转角的多押分组**：相邻击打的转角不超过 `ChordAngle`、间隔不超过 `ChordMaxGap` 时继续加入组，最多四个击打。默认分别是 30° 与 60 ms；角度比较有 0.1° 容差，用于游戏单精度误差。
2. **未知转角的回退分组**：仅在角度未知时使用 `ChordWindow`，按与组首击打的时间差判断，默认 35 ms。极快但转角正常的连打不能因时间很短就当多押。
3. **多押用手**：双押同手；三押是优先手两个键加另一手一个键；四押占用四轨。惯用手与多押用手是独立设置，后者可选另一只手。
4. **单押状态机**：以重置间隔 `R` 为界。均匀慢速单押倾向主手食指；`R/2 < 间隔 ≤ R` 倾向两手食指交替；更快时允许轮指。默认 `R=165 ms`，一半是 82.5 ms。
5. **让手与连按避让**：紧邻多押的单押可让给另一手；当前单押与紧邻上一音在 `JackWindow` 内同轨时尝试换轨。这些步骤可覆盖基础状态机。
6. **外轮与镜像**：外轮对符合条件的相邻同手音进行调整，尽量从外侧指到食指；惯用左手通过最终整体镜像得到。审核偏好在同一管线中处理符合条件的单押片段，不重做多押分组。

全部参数和所选排法必须随导出保存，包括 `ChordAngle`、`ChordMaxGap`、`ChordsOnOtherHand` 和审核短串参数。只记录旧版七个时间参数，不足以重建当前结果。

## 不应扩大理解的保证

- 「相邻连按」指相邻提示之间共享轨道，不覆盖中间隔了其他音符的所有重复用指。
- 外轮、让手和片段衔接会影响局部手序；相同局部间隔不代表不同前后文必定产生相同形状。
- 长按时长保留，不等于已经实现完整的长按占手优化。审核偏好在含长按的谱面上整体沿用原排法。
- 随机与边界测试是覆盖证据，不是对所有参数组合与关卡的数学证明。游戏实际手感仍需玩家验证。

## 离线实现与自动对照

C# 离线解析继续留在 `tools/Preview.cs` 的 `AdofaiTiming`，使用同一份 `FloorHits` 筛选击打、判断与累计角度。它保留上游 pathData、Pause 和出发间隔计算，并补充已知相对路径、旧版 Pause 迁移及必要 JSON 兼容；不另建第二份 C# 解析器。

JavaScript 导入器实现相同的有限离线流程；JavaScript 排键实现则通过 C# 生成的合成基线对照当前 `NotePlanner`。自动测试覆盖带角度/未知角度、双押/三押/四押、两种排法、参数变化和镜像；Preview CLI 整谱对照另外核对双方支持的时间事件、pathData、转角和排键结果。

离线读取器明确拒绝未支持的时间或输入事件，不能静默略过后把结果标作真实游戏谱面。即使 JS 和 C# 完全一致，也只说明两份离线实现一致；游戏倒计时、校准和完整事件系统不在这一保证内。正式审核优先使用游戏内导出的真实砖块数据。

## 历史证据的适用范围

旧 PR 基于纯时间判双押版本及不含转角的个人审核文件提出过偏好候选。那些命中统计不用于验证当前转角判多押算法，也没有据此修改默认排法。未来应使用带角度和完整参数的新游戏快照，先精确复现对应原排法，再分别报告人工改键的命中、已审核原样位置的变化及未审核位置的变化。
