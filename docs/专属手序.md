# 专属手序

自动排键只看这一关自己的砖块，对所有谱一视同仁；专属手序是玩家给某首歌手排的一份，可以分享，社区一起做。两者分开：自动排键的规则不为任何一张谱特化，专属手序是玩家自己的内容，放进文件夹才用。

## 玩家怎么用

1. 进到这首歌（还没按键开始、暂停、死亡画面、通关画面都行；关卡编辑器里要在试玩中），F8 → 专属手序 →「编辑本关手序」
2. 浏览器打开手序编辑器（`Mods/RhythmHint/Editor/index.html`），自动载入这一关：砖块、游戏里正在用的手序、两种自动排法（标准、交替优先）做对照、节拍线、轨道形状、音乐和波形
3. 改完点「保存到游戏」：Edge、Chrome 第一次要选一下 `Mods/RhythmHint/Fingerings` 文件夹，以后直接写进去；别的浏览器会下载文件，按提示放进去
4. Mod 每秒看一次这个文件夹，有变化就重排，关卡里马上换上
5. 分享：把 `Fingerings` 里的文件发给别人，对方放进同一个文件夹就行。文件里不带音乐
6. 接着改（2026-11-18 用户：很多人一次改不完整张谱就把网页关了，不开游戏很难再找到网页和之前改的东西）：编辑器把每一关现在的样子（每个音符按哪几个键、作者、说明，保存过没有）随时存在浏览器里，关网页、换关卡都不丢，再打开这一关自动接着改，提示条上点「放弃」回到游戏这次给的样子。游戏每次「编辑本关手序」把那一关另存到编辑器目录的 `recent/`（最多 10 关，同一份谱面只留最新的），编辑器左边「历史」列出这些关卡和各自的进度，点一下带着音乐、轨道预览打开。不开游戏时直接打开 `Mods/RhythmHint/Editor/index.html`（收藏网页，或者 F8 → 专属手序 →「创建桌面快捷方式」在桌面放一个带编辑器图标的快捷方式 `RhythmHint 手序编辑器.lnk`（`ShellLink` 按 MS-SHLLINK 直接写，不开 PowerShell；图标是 `Editor/icon.ico`，用 `tools/make-editor-icon.py` 生成）。不用 .url：路径里有中文时实测打不开；.html 启动页能打开但只有浏览器的图标），先显示最近一关

设置里「使用专属手序」关掉就全部用自动排键；状态写在「排键」页的「专属手序」一节。

## 怎么认出是哪一关（手序跟着歌走）

只看谱面本身，曲名、文件名都不参与判断（`FingeringMatcher.Choose`）。进关卡时依次：

1. **玩家选过**：这一关（按谱面指纹记在设置的 `FingeringChoices` 里）选过用哪份、或选了都不用，就照选的；文件不在了当没选过
2. **谱面指纹完全一样**：文件的 `charts` 里有这一关的指纹（`CustomFingering.ChartPrint`，按砖块节奏算）就直接用。同一张谱换文件名、换电脑都一样
3. **按节奏对齐**：谱面更新过时，把每份手序和这一关的砖块对齐，对上 80% 以上、并且比第二名多 10% 以上才自动用
4. **不确定**：有对上 30% 以上但不够确定的（比如同一首歌放了好几份），不猜，设置「排键」页的「专属手序」一节列出候选让玩家选，选了就记住

节奏对齐的细节：

- 比的是每块砖「和前一块的间隔、转角、有没有长按」：间隔差 4 毫秒或 3% 以内、转角差 1.5° 以内算同一块。不看绝对时间和砖号，所以改了偏移、中间加删了砖，后面的照样对得上；改了某块砖的角度只影响那一块
- 用最长公共子序列（限制在对角线附近的一条带里算），只认连续对上至少 8 块的整段：节奏只有几种取值，两首无关的歌零散地也能「对上」一大半
- 对上的砖用专属手序（作者和玩家惯用手不同时整体左右镜像，长按按比例换成本关的时长），对不上的用自动排键补；一个自动音符只有一部分砖对上时，压在它上面的专属音符也退回自动，保证每块砖正好一个提示
- 有对不上的地方：状态写「有 N 处对不上」，开局在面板上提醒一次（同一首歌、同一个结果重开不再提醒）
- 键数不同的手序不套用（以后有六键、八键时）

编辑器打开时，自动补上的音符描黄色虚线，右上角写「N 处待检查」，按 N 跳到下一处；改完保存，新的谱面指纹会加进文件的 `charts`（旧的也留着），以后这一版就直接认出来。

## 文件格式（rhythmhint-fingering，第 1 版）

UTF-8 的 JSON，Mod（`CustomFingering`）和编辑器（`model.js`）各写一份读写，格式相同：

```json
{
  "format": "rhythmhint-fingering", "schemaVersion": 1, "keys": 4,
  "song": "曲名", "artist": "曲师", "charter": "谱师", "author": "手序作者", "comment": "说明",
  "leftHanded": false, "updatedAt": "2026-11-18T00:00:00Z",
  "charts": ["谱面指纹", …],
  "hits":  [[砖号, 时间（秒）, 长按（秒）, 转角（度）或 null], …],
  "notes": [[第一块砖号, 最后一块砖号, [[轨道, 长按], …]], …]
}
```

- `hits` 是做手序时这一关要按的砖，按砖号、时间排好；节奏对齐靠它
- `charts` 是这份手序认得的谱面指纹：做手序时那一版，以及作者后来为更新版重新保存时的各版；旧文件没有这一项时自动补上 `hits` 那一版
- `notes` 按顺序、不重不漏地覆盖 `hits`；轨道 0–3 是 D F J K，一个音符 1 到 `keys` 个键；允许跨手双押（自动排键不会这样排，玩家可以）
- `leftHanded` 是作者的惯用手；读的时候比 Mod 支持的版本新就拒绝（提示更新 Mod），字段不对就跳过这一份并在设置里列出、日志写原因
- 文件超过 20 MB 不读

## 编辑器

`src/RhythmHint.Editor`，原生 JS 加 Canvas，不依赖任何库，双击就能离线打开；随 Mod 装进 `Mods/RhythmHint/Editor`。界面五种语言（默认跟 Mod 的界面语言），深色画布加浮动面板（参考 ComfyUI）。

- 中间是当前手序，左右两列是两种自动排法，和当前不一样的地方亮起来；能对选中的或整首套用
- 左边是小节号、时间和波形，右边是两下之间的间隔（毫秒、几分音符），同一个键 150 毫秒内连按标红（阈值可调）
- 右上是检查器：时间、砖号、前后间隔、来源（专属 / 自动补齐 / 已修改），点键位改键，多押点够个数生效
- 右下是轨道预览（游戏里的砖块路径和星球，跟着播放走）和全曲概览
- 操作：拖动换轨；选中后按 D F J K（玩家自己设的四个键）、←→、M 镜像；Ctrl+Z / Ctrl+Shift+Z；空格播放；滚轮滚动、Ctrl+滚轮缩放、空格拖动画面；`[` `]` 设循环；改动自动存草稿（浏览器本地），下次打开同一关会问要不要恢复

### 音乐、画面和打拍声

游戏把关卡写进 `Editor/session.js`（`window.RHYTHMHINT_SESSION`），同时另存到 `Editor/recent/<谱面指纹>.js`，`recent/index.js`（`window.RHYTHMHINT_RECENT`）列出最近的关卡（`SessionLibrary`）。编辑器从本机打开，通过同目录的脚本载入关卡，换关卡时再插一个脚本载入 `recent/` 里的那一份；音乐也放在 `recent/` 里跟着关卡留着，超出 10 关的和没人用的文件删掉，被浏览器占着的留到下次。改到一半的进度在浏览器里按谱面指纹存（`rhythmhint.editor.draft.<谱面指纹>`）。自定义关卡直接拷贝歌曲，官方关卡用 `AudioDump` 导出 WAV。官方音乐还没载入时，Mod 临时载入音频数据，读完再释放。Mod 能读取采样时会附上波形。对于流式 MP3，Mod 还可用游戏自带的 MP3Sharp 计算波形。本机游戏的 Managed 程序集中没有找到 Vorbis 解码器，流式 OGG 可能只有音乐。导出失败时仍保留偏移、音高和画面校准，手动选择同一首歌也能沿用。

- **关卡偏移**由 `MusicTiming` 计算。游戏导出用 `关卡 offset − 起始一拍 × adjustedCountdownTicks`。`adjustedCountdownTicks` 是倒计时拍数除以倒计时变速倍率。`CalculateFloorEntryTimes` 已把其中的「倒计时拍数 − 1」拍算进砖块时间。离线读谱的砖块没有倒计时，换算为 `关卡 offset − 起始一拍`。四组真实数据在 `MusicTimingTests`，此前九张工坊关卡的离线复核最佳平移均在 ±10 毫秒内。播放中的实测差值只用于写日志对照。
- **音乐和画面**按秒换算。`音乐拍点时间 = 音乐文件位置 − 关卡偏移 − 本歌手动偏移`，`画面时间 = 音乐拍点时间 − 游戏画面校准`。画面校准取自 `scrConductor.calibration_v`，存在 `audio.calibration`，旧会话缺这个字段时取 0。音符、判定线和轨道共用画面时间。波形和概览用同一个换算回到音乐文件取样。每首歌的手动偏移存于 `songOffsets`。音乐的节拍先响就减小，音符先到线就增大。
- **打拍声**跟音乐拍点走。浏览器生成音频的时刻和声卡实际播到的时刻之间有缓冲。`audio.js` 用 `AudioContext.getOutputTimestamp()` 把媒体位置对应到输出采样，平滑相邻帧的几毫秒抖动，再提前 120 毫秒排声。浏览器缺少输出时间戳时用可用的延迟估计。暂停、定位、变速、切换循环或关掉打拍声时清理旧队列。练习变速时音乐的音高随速度改变，避免浏览器保音高处理移动瞬态鼓点。
- **关卡音高**取自谱面设置。编辑器以「关卡音高 × 练习速度」播放，音乐和砖块共用这个速度。例如 75% 音高的谱面选 0.5×，每秒经过 0.375 秒原曲。定位、波形和偏移仍用原曲秒数，旧会话默认 100%。
- **音色**沿用关卡的 `scrConductor.hitSound`。Mod 从 `AudioManager.audioLib` 取已载入的 `snd` 加打击声名字，默认 Kick 对应 `sndKick`，以 WAV 放进会话。开打后也会缓存一份 `Editor/hitsound-名字.wav`，下次开局前就能使用。两处都取不到时编辑器合成打拍声。

在游戏里按 F8 → 专属手序 → 编辑本关手序会重新导出。日志里的「编辑器：偏移 …」列出关卡 offset、起始一拍和倒计时拍数，「编辑器：游戏的画面校准 …」列出单独作用于画面的毫秒数。

### 轨道预览

每块砖按游戏的 `entryangle` 和 `exitangle` 单独绘制，尖角、平头。`PathAngles` 用相邻且未被移动的砖核对角度约定，核对失败时用相邻位置。这样被挪开的砖之间不会多出斜线。

Mod 从 `levelData.Encode()` 取 MoveTrack、PositionTrack、AnimateTrack 事件和相关设置放进 `session.fx`。`fx.beat` 来自事件所在砖块的速度，用于把事件拍数换算成秒。`trackfx.js` 计算每块砖的位移、旋转、缩放、透明度和出现消失动画，`track.js` 负责绘制。镜头跟着星球，画面高约 10 个单位。缓动采用 DOTween 同名公式，位移以砖长 1.5 为单位，出现消失的形态与时长为近似。颜色、轨道样式、装饰物和谱面镜头不在重放范围内。

有些谱面把整段轨道藏起来，用装饰物指路。移动轨道把透明度降到 0.12 以下，或把两个轴都缩到原尺寸的 5% 以下时，预览以 16% 不透明度画出砖形，并继续叠加原来的出现消失动画。工坊 3386617648 的第 392 块在谱面 1:17.682 附近，可以用来复核这段虚影。

## 开发

- 不开游戏看编辑器：`dotnet run tools/Preview.cs -- 关卡.adofai --editor-session src/RhythmHint.Editor`，再打开 `src/RhythmHint.Editor/index.html`（离线近似：轨道按谱面方向、PositionTrack 静态偏移和 ScaleRadius 砖距还原，包含中旋折返。没有波形和游戏的打击声；歌曲文件在关卡旁边就一起拷过去）。`session.js`、`recent/` 不进仓库
- 测试：`node --test src/RhythmHint.Editor/tests/*.test.cjs`（数据层、五种语言齐全）；C# 的 `CustomFingeringTests`（格式校验、跟着歌走）、`EditorContractTests`（两边文件约定）
- 两边文件约定：样例在 `src/RhythmHint.Editor/tests/fixtures/`。`session.json`、`recent.json` 由 C# 测试生成，`saved.json` 由编辑器的 node 测试生成、C# 读回。格式改了时设 `RHYTHMHINT_UPDATE_FIXTURES=1` 先跑 C# 测试、再跑 node 测试，看 diff 再提交
- 改编辑器的界面文字：五种语言都写在 `i18n.js`，`i18n.test.cjs` 检查句句齐全、占位符一致、界面代码里没有写死的中文
