# 排法：标准和交替优先

设置「排键」页的「排法」有两种，默认「标准」：

| 界面上叫 | 代码里 | 说明 |
| --- | --- | --- |
| 标准 | `FingeringStyle.TimeReset` | 时间重置法（规则见开发说明「排键规则」），默认 |
| 交替优先（试验性） | `FingeringStyle.ReviewPreferenceV1` | 在标准排完的基础上，把一部分单押片段改成左右食指交替（来自 PR #1 的审核偏好，代码里的名字沿用） |

两种排法都只看这一关自己的砖块，共用转角判多押、三押四押、长按和多押用手；硬约束一样：每块砖一个提示、自动排的双押同手、左撇子整体镜像、不加楼梯。

## 交替优先改了什么

只对不含长按的谱面调整单押，不改分组、音符时刻、砖块范围和长按；含长按时整首和标准一样（还没有长按的样本支持重新分配占手）。

- **多押附近让手**：有效范围取 `min(ChordFocusWindow, ResetWindow)`，默认不超过 130 ms（主手重置间隔 2026-11-19 从 165 改为 130），离开这个范围就按正常起手
- **中速单押片段**：由多押或大于重置间隔的空隙分开；片段里每个间隔都在 `ResetWindow / 2` 到 `ResetWindow` 之间时，改成左右食指交替
- **等速短串**：只在开着轮指、外侧手指先按时考虑。音符数、间隔和均匀度都在下表范围内时，改成左右食指交替；最长间隔还不超过 `ResetWindow / 2`
- **整段衔接**：先试主手起手，再试另一边；和前后音符连按、或出现食指→外侧手指时保留标准的排法。最后照样按惯用手镜像

## 短串参数

在设置里紧挨着「排法」、缩进一格显示（只有选交替优先时出现）：

| 设置里叫 | 参数 | 默认 | 含义 |
| --- | --- | ---: | --- |
| 短串最短间隔（毫秒） | `ReviewShortMinGap` | 60 | 每两下至少隔这么久 |
| 短串最长间隔（毫秒） | `ReviewShortMaxGap` | 82.5 | 每两下最多隔这么久，还不超过主手重置间隔的一半（默认重置间隔 130 ms 时实际是 65） |
| 短串最少音符数 | `ReviewShortMinNotes` | 4 | |
| 短串最多音符数 | `ReviewShortMaxNotes` | 5 | |
| 节奏允许误差（毫秒） | `ReviewTimingTolerance` | 1 | 最长和最短间隔之差的上限（节奏要均匀） |

46.875 ms 的极快片段和 6 个音以上的持续轮指不算短串。这些阈值是待验证的候选范围，不是每个玩家的手速边界；哪套排法更好要看多个人的反馈和 `tools/Preview.cs` 的指标。

## 测试

C# 回归测试（`ReviewRulesTests`）检查参数边界、镜像、多押用手、长按回退和结构不变；试验台网页的 JS 排键和 C# 用自动生成的合成谱逐个音符对照（`tools/planner-js/planner-parity.test.cjs`）。离线预览选这个排法：`dotnet run tools/Preview.cs -- 关卡.adofai --alternate`。
