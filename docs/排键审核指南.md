# 排键审核指南

审核的目标是保留自动生成的排键，让玩家修改并说明原因，再据此提出可验证的通用规则。审核文件不会直接改变游戏谱面；Mod 也不读取个人审核文件套用固定答案。

## 打开和保存

1. 在游戏中加载要审核的关卡，打开 Mod 设置的「状态」页，导出当前关卡排键。文件位于 `游戏目录/Mods/RhythmHint/Reviews/`；它记录实际时序、转角和当前排法。
2. 双击 `tools/review-editor/index.html`，点击「打开谱面」选择导出的 JSON。也可直接打开 `.adofai` 开始离线预览，不必先转换。
3. 点击「载入音乐」，单独选择关卡目录里的音频。浏览器不会自动读取谱面旁边的歌曲；音乐与谱面均留在本机。
4. 拖动音符换轨，选中一段后填写理由、标记已审核。认可原排法也可以标记，不需要先改键。
5. 点击「导出审核」保存完整 `.review.json`。再次打开该文件可保留修改继续；摘要文件不能替代完整审核文件。

直接打开 `.adofai` 会重新生成自动排键。要继续已有修改，请打开审核 JSON，或恢复与该原谱匹配的本机草稿。浏览器草稿可能因隐私模式、换浏览器或存储限制不可用，因此以下载的审核文件为准。

## 操作方式

- 滚轮浏览；Ctrl + 滚轮缩放；左侧概览用于快速定位。
- 点击或框选音符，Shift 追加选择；横向拖动或左右方向键移轨，M 镜像。多押可单独拖动其中一个按键。
- 空格播放/暂停，Home 回起点，底部调整速度、音乐偏移及 A/B 循环。
- Ctrl + Z 撤销，Ctrl + Shift + Z 重做，Ctrl + S 导出审核。

界面保留原始击打时间、砖块范围、音符按键数量和长按时长；只能修改轨道。节拍网格是辅助参考，不会量化或移动原始时间。更多操作见 [Studio 使用说明](../tools/review-editor/README.md)。

## 选择排法

Mod 默认仍使用时间重置法。可以在排键设置中主动选择审核偏好排法，试用后随时切回；两者共享上游转角判多押与三押/四押逻辑。具体范围和参数见[可选排法说明](审核偏好实验规则.md)。

请审核文件本身所记录的排法和参数。不能将旧算法的审核修改直接当作新算法的正确答案；同名关卡也可能在时序、转角或参数上不同。

## 离线预览的边界

C# 离线读取器仍是 `tools/Preview.cs` 内的唯一 `AdofaiTiming`，没有另建一份 Reference 解析器。浏览器实现对齐它的近似计算：支持非空 `angleData`、绝对方向及 `!` 中旋组成的 `pathData`、现代格式的已知相对方向，以及砖块上的 `SetSpeed`、`Twirl`、`Pause` 和明确允许的表现事件。

版本 9–16 的 Pause 迁移、原始字符串控制字符及旧谱数组属性后遗漏的逗号有兼容处理。旧式 sprite pathData 的相对方向仍不支持。Pause 的主体计算继续使用预览器的出发间隔公式；游戏倒计时、校准和完整事件系统没有被完整模拟。因此浏览器与 C# 逐字段一致，也不表示已经复现游戏的全部行为。复杂关卡、实际手感审核和规则总结，以游戏内导出的实际砖块数据为准。

遇到 Hold、MultiPlanet、AutoPlayTiles、非零时序事件角度偏移或未知事件等未支持情况，工具会明确拒绝，并提示使用游戏导出。

## 写下有用的反馈

说明手感及前后文，例如「这四下想用食指交替，第三下切到外侧指不顺」「这里多押后仍需换手」「这一段原排法可以」。只记录改动而不标记认可位置，会把尚未看过的音符混同于认可样本。

归纳规则时分别检查：真正改键的位置、明确审核但保留原排法的位置、尚未审核的位置。候选规则应记录触发条件、支持例、反例和验证范围；新排法在其他位置产生的变化需要复审，不能自动判错或判对。

## 开发命令

需要 .NET 10 SDK；编译 Mod 另外需要本机游戏和 UMM DLL。

```powershell
dotnet test tests/RhythmHint.Core.Tests
node --test tools/review-editor/*.test.cjs
dotnet run tools/Preview.cs -- "关卡.adofai" --review-export "Charts/reviews/关卡.review.json"
dotnet run tools/Preview.cs -- "关卡.adofai" --review-rules --review-export "Charts/reviews/关卡-偏好.review.json"
node tools/build-review-editor.cjs "Charts/reviews/关卡.review.json" "Charts/reviews/关卡.html"
```

最后一条命令生成包含原谱的独立编辑器 HTML，双击即可使用，修改仍另存为审核 JSON。个人谱面、音乐及审核证据应留在被忽略的 `Charts/` 或 `artifacts/`，不放入代码仓库或 Mod 安装包。

Node 对照测试还需要 .NET 10 和 Python 3。可通过 `DOTNET_HOST_PATH`、`PYTHON` 指定可执行文件，未设置时从 PATH 查找。测试只用合成数据，不依赖开发者桌面路径或未提交的私有文件。

## 审核文件

`rhythmhint-review` v1 的时间均为秒，轨道编号为 0–3。主要字段：

- `notes` 保留不可变的自动排键；`review.edits` 以 `noteId` 关联修改、理由及审核状态。
- `sourceHits` 保留重跑所需的原始击打，包含时间、砖号、长按以及已知转角；未知转角明确表示为未知，不能用 0 冒充。
- `options` 包含排法及全部影响排键的参数；`algorithm` 和 `chartId` 用于区分生成版本与输入，防止草稿混用。
- `source` 区分游戏导出、离线近似和演示；`sourceFile` 与 `timing` 可保存音乐偏移及辅助时间信息。

旧文件仍可用于手工审核。缺少角度、版本或必要参数的旧快照，不应被解释为当前转角算法的已验证输入；自动对照必须先验证基线能够精确重建。
