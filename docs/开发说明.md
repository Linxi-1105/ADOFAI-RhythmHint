# 开发说明

## 结构

| 目录 | 内容 |
|---|---|
| `src/RhythmHint.Core` | 纯逻辑，netstandard2.0，不引用 Unity：排键参数（`FingeringOptions`）、按间隔排键（`NotePlanner`）、游戏画面缩放（`ViewportShrinker` / `ViewportMath`）、节拍线和拍点判断（`BeatGrid`）、死亡后定住的画面时钟（`DisplayClock`）、入场 / 出场动画进度（`PresenceAnimator`）、设置页演示谱（`DemoChart`）、哪些砖要按和砖之间的转角（`FloorHits`）、按住中的长按（`Holds`）、界面翻译的查表和回退（`Translator` / `Languages` / `Message`） |
| `src/RhythmHint.Mod` | UMM Mod，net48，引用游戏 DLL。Core 的源码直接编进同一个 DLL。`Overlay` 决定画关卡还是演示，`DemoPlayer` 播放演示（有菜单音乐时跟 `scrConductor.songposition_minusi` 和 `bpm` 同步，没有时用音频时钟 + 嗒声），`Lang` + `Languages/*.json` 界面翻译（见「多语言」），`TopBarView` / `LaneView` 绘制（四轨音符有横条和圆形两种样式，圆形和太鼓条共用 `BallSkin` 的球和判定圈画法；圆形的判定点在判定圈圆心，轨道分隔线通到底、一条细线串起判定圈，命中时是判定圈周围的圆形柔光而不是横条那种往上的光柱） |
| `src/RhythmHint.Reference` | **开发专用**：读 Phira（RPE）谱、把谱对齐到关卡、和自动排键逐个比较。Mod 不引用它，游戏里不读任何外部谱面 |
| `tests/RhythmHint.Core.Tests` | Core 和 Reference 的单元测试（xUnit v3） |
| `tools/Preview.cs` | 离线预览：不开游戏，用文字画出某一关的排键；可选给一张自己手排的参考谱做手感对照 |

## 原则

- **每一关只按自己的砖块排键**，不为任何一张谱做特殊处理。参考谱只用来衡量通用规则像不像用户的手法，结果不写回 Mod。
- 每块要按的砖都对应一个提示；`PlannedNote.TileIndex..LastTileIndex` 覆盖它包含的砖（伪多押是几块），测试保证不漏不重。

## 编译

需要 .NET SDK 10 和本机装好的游戏 + UMM（Mod 要引用游戏的 DLL）。

```bash
cp local.props.example local.props
```

然后在 `local.props` 里填游戏目录（或设环境变量 `ADOFAI_DIR`）。

```bash
dotnet test tests/RhythmHint.Core.Tests
```

```bash
dotnet build src/RhythmHint.Mod -c Release -p:Deploy=true
```

`-p:Deploy=true` 会把 `RhythmHint.dll`、`.pdb`、`Info.json` 复制到 `游戏目录\Mods\RhythmHint\`，不动已有的 `Settings.xml`。游戏要先关掉。
`Info.json` 由编译生成，版本号只在 `Directory.Build.props` 里改。

## 发布

```bash
dotnet build src/RhythmHint.Mod -c Release -p:UmmPackage=true
```

在仓库根目录 `artifacts\` 生成 `RhythmHint-版本.zip`，里面只有 `RhythmHint/RhythmHint.dll` 和 `RhythmHint/Info.json`，
可以直接在 UMM 安装器（`UnityModManager.exe`）的 Mods 页点「Install Mod」选它，或拖进窗口安装；也可以手动解压到 `游戏目录\Mods\`。
`artifacts/` 不进仓库。压缩包用 MSBuild 的 `ZipDirectory` 生成，路径分隔符是标准的 `/`；
0.9.1 用 Windows PowerShell 5.1 的 `Compress-Archive` 打包，压缩包里的路径是 `RhythmHint\Info.json`，不是标准写法，不要再用它打包。

同一条命令还会生成 `artifacts\Repository.json`，是 UMM 的更新清单（版本号和压缩包下载地址）。

发版顺序：
1. 改 `Directory.Build.props` 的版本号；更新记录 `CHANGELOG.md`（中文）和 `CHANGELOG.en.md`（英文）的「未发布」「Unreleased」改成「版本号 · 日期」
2. 测试、格式检查，跑上面的打包命令
3. 在 GitHub 新建 Release（标签 `v版本`），说明里的「这次更新」复制两份更新记录里的那一节（中文在前、英文在后），
   附上 `RhythmHint-版本.zip` 和 `Repository.json` 两个文件

国内下载（夸克网盘、Q 群文件）：UMM 单独一个包（官方 UMM 安装器原样加一份中文安装说明），只传一次；
之后每个版本只传同一个 `RhythmHint-版本.zip`。0.9.1 的旧包（反斜杠路径）UMM 安装器装不上（`InstallMod` 里 `Substring` 报错），不要再往外发。

代码检查：

```bash
dotnet format src/RhythmHint.Core/RhythmHint.Core.csproj --verify-no-changes
```

用自己的谱面跑私有测试（不设环境变量时这个测试会明确跳过）：

```bash
RHYTHMHINT_PRIVATE_PEZ="E:/游戏铺面/Phi/新第二版.pez" dotnet test tests/RhythmHint.Core.Tests
```

离线预览和手感对照（`--reset` `--jack` `--chord` 可以临时试排键参数，单位毫秒，`--no-roll` `--inner-roll` 关轮指 / 改内轮，`--left-handed` 左撇子，`--chord-other-hand` 多押用另一只手，放在最后；支持 angleData 和 pathData（绝对方向字母）；会打印「跳轨」比例、孤立音符、双押左右手、停顿后主手起手的比例）：

```bash
dotnet run tools/Preview.cs -- "关卡/main.adofai" "参考谱.pez" --from 60 --seconds 4
```

### 更新提示

Info.json 的 `Repository` 指向 `仓库/releases/latest/download/Repository.json`（GitHub 跳转到最新一个 Release 里的那个文件），
所以清单只在正式发布后才变，不用提交到仓库。仓库地址只在 `RhythmHint.Mod.csproj` 的 `RepoUrl` 写一处。

- 游戏里的 UMM 读这个清单，版本更高就填 `ModEntry.NewestVersion`（UMM 的 Mods 列表里本 Mod 旁边出现更新图标）。
  UMM 默认（`Params.xml` 的 `CheckUpdates=1`）每天只在第一次启动游戏时查一次：`LastUpdateCheck` 是今天就不查，日志里也没有「Checking updates.」；
  查之前先 ping 8.8.8.8，不通也不查。查到的结果 UMM 不存
- Mod 不联网，只读这个值（`UpdateNotice`）：一看到就记进 `Mods\RhythmHint\Settings.xml` 的 `LatestVersion` 并写日志「UMM 查到新版本」，
  当天再开游戏照样提示，装上新版后自然不提示。设置窗口标题栏显示「有新版本」，状态页顶部给下载页按钮
- UMM 安装器的 Mods 页读同一个清单，右键「Update to 版本」按 `DownloadUrl` 下载压缩包并安装
- 漏传 `Repository.json` 不影响安装，只是玩家收不到提示；没联网、国内连不上 GitHub 时也只是不提示
- 1.1.0 及更早的版本 Info.json 里没有 `Repository`，收不到提示

在游戏里试提示（游戏关着做，UMM 退出时会把内存里的 `Params.xml` 写回去）：
1. 写一个版本号更高的假清单（格式同 `artifacts\Repository.json`），用 `ModRepository` 指过去装进游戏
2. 把 `Managed\UnityModManager\Params.xml` 的 `LastUpdateCheck` 改成昨天，让 UMM 这次启动会查
3. 开游戏看提示；再开一次（这次 UMM 不查）提示应该还在
4. 试完删掉 `Mods\RhythmHint\Settings.xml` 里的 `LatestVersion`（不然一直提示假版本），不带 `ModRepository` 再装一次

打发布包时改了 `ModRepository` 会直接报错，免得发出去的包指向本地文件。

```bash
dotnet build src/RhythmHint.Mod -c Release -p:Deploy=true -p:ModRepository=file:///D:/假清单目录/Repository.json
```

## 排键规则

### 规则（1.0.0，`NotePlanner`）

2026-11-16 玩家反馈手序不对，调研了原版和同类 Mod（下面「参考」），用户决定按 LaneReader「时间重置法」的思路改。
每一下按哪根手指只看和前面几下的间隔，不看 BPM、小节、拍点，也不切段。R = 主手重置间隔（`ResetWindow`，默认 165 ms），主手是右手。

1. **合成时刻**（多押，2026-11-17 改，见第 11 条）：相邻两块转角 ≤ 30°、相隔 ≤ 60 ms 算同时按，一块接一块串成双押、三押、四押；
   连成 5 块以上是连打，全拆开。读不到转角时退回旧规则：和这一组第一块相隔不到 35 ms。
2. **单押的状态表**（上一下用的手指 + 间隔 d；右手最后一次按到现在 dRight）：

   | 上一下 | 条件 | 这一下 |
   |---|---|---|
   | 没有 / D / 左手双押 | — | J |
   | J | d > R | J（慢：一根手指点得过来） |
   | J | R/2 < d ≤ R | F（左右食指轮流） |
   | J | d ≤ R/2 | K（太快：右手两根手指轮指） |
   | K / 右手双押 | d > R | J |
   | K / 右手双押 | d ≤ R | F |
   | F | d ≤ R/2 或 dRight ≤ R | D（右手刚轮过，左手也轮） |
   | F | 否则 | J |

   所以均匀的连打：> 165 ms 是 `J J J`，83–165 ms 是 `J F J F`，≤ 82 ms 是 `J K F D` 循环；停下来（> R）总是回到 J。
   关掉轮指（`UseRoll`）时 K、D 两行都换成食指交替。
3. **外轮**（`OuterRoll`，默认开）：轮指出来的外侧手指和它前一下（同一只手的食指）换位置，`J K F D` 变成 `K J D F`（用户习惯的 4312）。换了会连按的不换。
4. **双押优先右手**：放 J K，右手上一下刚按过（< 150 ms）才放左手 D F。
5. **右手专心按双押**（`ChordFocusWindow`，默认 450 ms）：用户试打反馈「J 单押 → J+K 双押 → J 单押」右手食指、中指配合不过来。
   紧挨着双押（前一下或后一下就是双押）、隔得不超过 450 ms 的单押放另一只手（双押在右手就放左手食指 F，F 刚按过才用 D）；
   前后都是双押时看离得近的（一样近看后面的）。中间的单押照常排。
   第一版把双押前后 450 ms 内的单押全放左手、F D 轮流，用户随即反馈「不要有 21 式，尽量避免从内向外的楼梯」，改成只换紧挨着的那一下。
   让不开的只有「左手双押和右手双押中间夹一个单押、左右手都刚按过」这种。
6. **不出现食指→外侧手指**（用户：不要有 21 式，尽量避免从内向外的楼梯）：同一只手先食指再外侧手指（F→D、J→K）挨得近（≤ R）时：
   - 外轮换不了顺序（换了会连按，通常是前后夹着让手的单押）：这一下改按另一只手的食指，左右手轮流
   - 下一下要让给左手食指、又挨得不到 150 ms：这一下先用 D，下一下再按 F（从外向内）；双押在左手时（见 10）反过来，先用 K 再按 J
   本机 12 张关卡上 ≤ 165 ms 的 F→D、J→K 都是 0；还剩少量 187–300 ms 的「一下 J，隔一会儿接 K J D F 轮指」开头。
7. **连按**：同一条轨道连续按两下至少隔 150 ms（`JackWindow`）；规则排出来会连按时（多半紧跟在双押后面），换到离上一下最近的空轨道。比较时带 1e-6 容差。
8. **双押只能是同一只手**：轨道 0+1（D F）或 2+3（J K），**绝不跨手**（冰与火玩家的硬性要求）。
   三押必然用到两只手：按双押的那只手按两个键，另一只手的食指补一个（食指刚按过、会连按才用外侧手指）；四押四个键全按（第 11 条）。
9. **左撇子**（`LeftHanded`，设置里的「惯用手」，2026-11-16 用户要求）：上面 1–8 按右手为主手排完后，整体左右镜像（轨道 i → 3 − i，D↔K、F↔J）。
   于是慢的左手食指 F 连点、停下回 F、双押优先 D F、紧挨着双押的单押放右手、轮指 D F K J；双押同手、不出现食指→外侧手指这些约束镜像后照样成立。
   规则只写一份，左右手永远一致（测试 `LeftHandedIsTheMirrorOfRightHanded` 在随机谱上逐个音符核对）。
   `tools/Preview.cs` 的「跳轨」统计双押时只取编号最小的轨道，所以镜像后数字会略有不同（某关右手 8/504、左手 14/504），排法本身是对称的。
   试验台 `tools/layout-lab.html` 的 `planMod` 只做右手为主（默认），没有加左撇子。
10. **多押用另一只手**（`ChordsOnOtherHand`，设置里的「多押用手」，原名「双押用手」，2026-11-17 玩家反馈「双押用手和惯用手分开设置」）：
    按右手为主手的坐标写，第 4 条改成「双押优先左手 D F，左手刚按过才放右手」；第 5、6 条跟着换边：紧挨着双押的单押改用右手 J，
    下一下要让给 J 又太近时这一下先用 K。左撇子再整体镜像，所以四种组合只有这一份规则。
    存的是相对惯用手的选择（同惯用手 / 另一只手），默认同惯用手，老设置读进来排法不变。
    本机关卡 life（878 个双押）：双押右手 / 左手从 519 / 359 变成 359 / 519；停顿后第一下是单押的 95 次里主手起手 78 → 92；
    「跳轨」46.8% → 60.5%，因为左手双押取轨道 0、后面接右手 J 就算跳了两条，是这种手法本身的样子。
    试验台的 `planMod` 加了同样的开关，和 C# 在 200 张随机谱、两种设置共 80000 个音符上逐个一致。

11. **多押怎么认**（`ChordAngle` 默认 30°、`ChordMaxGap` 默认 60 ms，2026-11-17）：用户要识别三押、四押（Timeline 里有），
    玩家反馈旧版把快速轮指段识别成双押。旧规则只看时间（和第一块相隔 < 35 ms），两头都错：
    - Timeline 的三押是 180 BPM 下 15° + 15°（每块隔 27.8 ms，跨 55.6 ms），第三块进不了 35 ms，画成双押 + 单押；120 BPM 下 15° 的双押是 41.7 ms，也合不上。
    - life 里 1816 BPM 下 180°、908 BPM 下 90° 的连打每块只隔 33 ms，被合成一串双押。
    谱师画多押用的是很小的转角，快连打转角正常、只是 BPM 高，所以改成看转角（游戏里读 `scrFloor.angleLength`）。
    在本机创意工坊和本地共 37 张关卡上比较（分析脚本没进仓库）：

    | 分法 | 合出的多押 | 其中其实是均匀连打的 | 小转角（≤15°）多押没合上 |
    |---|---|---|---|
    | 旧：和第一块相隔 < 35 ms | 9007 | 4220 | 92 |
    | 转角 ≤ 30° 且 ≤ 60 ms（现在） | 4769 | 7 | 3 |
    | 只看节奏（比前后都挤一半以上） | 4944 | 0 | 10 |

    只看节奏会把连打里加倍速的小快段（1/16 里夹 1/32）当成三押，所以不用。转角上限 45° 时误合 29 处，20° 时多押只剩 289 个（大多数伪多押用 30°）；
    间隔上限取 45 / 60 / 80 ms 结果几乎一样。用瞬间超高 BPM 做的伪多押（转角大、间隔极小、前后都空）在这批谱里一处也没有。
    转角先和砖块时间核对（`FloorHits.CheckAngles`：间隔 ≈ 转角 / 180° × 一拍 / 速度倍率）。`angleLength` 记的是离开还是到达这块砖的转角没有文档，
    两种对法各算一遍，看多少对相邻砖块和中位比值相差不到 3%，用多的那种；都不到一半就退回只看时间，日志里写出两种对法各对上多少。
    比较转角时留 0.1° 余量（`NotePlanner.AngleTolerance`）：游戏里方向存成单精度浮点，30° 读出来是 30.000004° 或 29.999996°。
    第一版只看比值中位数、只留 0.000001° 余量，用户在 Timeline 里截到三押画成单押 + 双押、四个单押。实机日志确认 Timeline 按离开对上 100%、按到达 58%，
    即 `angleLength` 记的是离开这块砖的转角，问题出在浮点误差；加余量后游戏里是 847 个提示、三押 104、四押 5，和离线预览一致。
    两种对法的核对仍然每关都跑，转角万一对不上（游戏改了字段含义）会退回只看时间。
    Timeline 现在是三押 104 个、四押 5 个；life 的双押从 867 个降到 509 个，「两个多押挨得太近」从 520 处降到 256 处。
    试验台的 `toMoments` / `planMod` 同步，和 C# 在 240 张带转角的随机谱（含 1388 个三押、1465 个四押）共 84680 个音符上逐个一致；
    试验台自己读 `.adofai` 的结果和 Preview 导出在 Timeline、life 上逐块一致。

设置窗口里能调惯用手、多押用手、R、多押前后换手的范围、开关轮指和外轮、多押转角上限；主菜单演示里改了立刻看得到效果（演示谱第 14.5 拍是三押）。

### 参考（2026-11-16 调研）

- **原版「全节奏提示」**（B 站 Winkle雪线的合集）：视频左下角的键盘提示器会显示作者实际按的键。逐帧读了 XO、XT、It Go 三关：只用中间两个键；间隔 < 120 ms 几乎都交替，≥ 160 ms 基本一根手指连点；停顿之后约 97% 从同一个键起手
- **LaneReader**（github fallingCB/LaneReader）：默认「时间重置法」，就是上面的状态表；另一套从 ReADOFAIMacro 移植的「拆手序」按节拍分组（强拍主手），作者说三连音会错位
- **AdoFalling**：< 180 ms 四个键像楼梯一样依次滚，慢的 F J 交替；处理不了双押

### 历史

- 0.2.0–0.4.0：逐音符规则，参考作者手排 CE-TX 4K 谱的统计（快速连打食指交替、拍点右手）。参考谱对照工具仍在（`tools/Preview.cs` 第二个参数）
- 0.5.0–0.7.0：切段套模板（楼梯、折返楼梯、交互、交叉楼梯），整轮对齐、接缝衔接、同节奏同形状
- 0.8.0：用户要求优先交互，楼梯类默认关；联音改用 1243
- 0.9.0：楼梯类删掉；右手起手；双押优先右手。按 300 ms 切段，段内一律 F J 交互，超高速均匀段和联音用 1243
- 1.0.0：玩家反馈手序不对。旧规则的问题：160–300 ms 的音也左右交替（大家习惯一根手指点）；固定 300 ms 断段让同样的节奏手序不一样；联音改 1243 在慢交互中间插进「同一只手两下」。改成时间重置法，切段、交互模板、1243、按小节切段都删了

### 孤立音符（`LayoutStats.LoneNotes`）

和前一下、后一下都隔着 2 条以上轨道（双押按最近那条算）、且前后都挨着（≤ 300 ms）的音符，看起来像从队伍里掉出来的点。用户明确要求减少。

## 排键试验台网页（tools/layout-lab.html）

每段的结论（最顺手的方案、理由、手排轨道）和每次录制存在网页的 `db` 里（`verdicts`、`recordings` 两个集合），Claude 用 ArtifactData 读回来分析。

## 设置窗口

`SettingsWindow`（IMGUI `GUI.Window`）+ `WindowSkin`（深色样式、开关、带微调按钮的滑块）。每项都是「左边名字、右边控件」两栏对齐（开关、选项、滑块）；每行一样高（36）、控件上下居中、行间留 6（`WindowSkin.BeginRow / EndRow`）；说明只在名字说不清时写一句，放在控件下面。默认 F8 开关（`Settings.SettingsHotkey`），
UMM 页面只留状态和「打开设置窗口」按钮。窗口按 1080p 设计、用 `GUI.matrix` 缩放到当前屏幕；开着时每帧 `RequestPreview()`，
不在关卡里就播放演示。关闭时 `Settings.Save`。
每页底部有「恢复本页默认值」（`Settings.ResetPreview / ResetDisplay / ResetFingering / ResetHotkey`，从新建的 `Settings` 实例抄默认值，默认值只写在字段初始值里）；
点一次先变成「再次点击确认恢复」，3 秒内再点才生效，防误点。排键页恢复时保留惯用手和多押用手（玩家自己的习惯，不是调出来的参数）。

**不影响游戏**：IMGUI 画的窗口游戏的 uGUI 事件系统看不见，在窗口里点击、拖动原本会被当成击打或点到后面的按钮。
所以窗口底下垫一块自己建的透明 uGUI 挡板（`InputShield`：最上层的 Canvas + 透明 Image + 没有内容的 ScrollRect，每帧跟着窗口位置）。
游戏判断击打（`scrPlayer`，鼠标按下且 `EventSystem.IsPointerOverGameObject()` 时不算）和编辑器点选、滚轮缩放（指针在带 ScrollRect 的界面上时不缩放）都会因此忽略窗口里的操作。
窗口里不放输入框、也不录按键（打字会被当成击打）：按键框的键位只有默认的 D F J K 和「自定义」（原来的 S D K L 等三套预设已去掉），自定义用屏幕键盘点选（`KeyPicker`，选中第几个按键框再点键盘，点完自动跳到下一个；点了已分给别的框的键就两个框互换，拆分和互换在 Core 的 `KeyBindings`）；快捷键选预设，其他按键改 `Settings.xml`。
已知例外：自定义关卡选关界面（`scnCLS`）直接读 `Input.mouseScrollDelta`，在窗口上滚滚轮仍会翻关卡列表。

## 多语言

2026-11-18 用户要求：覆盖冰与火的主要国家，包括 README。

- **语言**：简体中文（原文）、繁體中文、English、한국어、日本語（`Languages.All`）。设置「状态」页的界面语言默认跟随游戏（每帧读 `RDString.language`，变了才重新算），
  游戏是还没有翻译的语言（西班牙语、俄语等）时显示英文。缺某句译文时先用英文、再用中文原文；繁体中文缺句直接用简体原文。
- **翻译表**：`src/RhythmHint.Mod/Languages/<语言代码>.json`，键是中文原文、值是译文，编进 DLL（`EmbeddedResource`，安装包还是只有 DLL 和 Info.json），
  用游戏自带的 Newtonsoft.Json 读。某个表读不了只记一条警告，那种语言退回英文，不影响 Mod 运行。
- **代码里怎么写**：马上要显示的文字写 `Lang.T("中文原文", 参数…)`；既要显示又要写日志的（状态、隐藏原因、演示说明）写 `Lang.M(…)` 做成 `Message`，
  显示时 `Lang.T(message)` 翻译，日志里 `message.ToString()` 是中文原文；参数里可以再放 `Message`，跟着一起翻译。
  参数用占位符 `{0}`（可带格式 `{0:0.#}`），不要写成 `Lang.T($"…")`；数字按固定区域格式填（小数点不会变成逗号）。
  英文状态名（`Countdown` 之类）、键名、语言名本身不翻译。
- **加一句话**：在代码里写 `Lang.T("…")`，再到四个 JSON 里各补一条译文。`TranslationTests` 会检查：代码里用到的每句四种语言都有、
  JSON 里没有用不到的句子、占位符和原文一致、Mod 界面代码里没有漏掉没走翻译的中文字面量（注释和 Logger 日志除外）。
- **加一种语言**：`Languages.All` 加一项（代码和用它自己文字写的名字），`Languages.FromGame` 加游戏语言的对应，新建 `Languages/<代码>.json`，
  再加一份 `README.<代码>.md` 并在每份 README 开头的语言切换行里加上。
- **排版**：英文、韩文的名字常比中文长，`WindowSkin.LabelWidth` 按上一帧量到的最长名字在 250–380 之间自动加宽（只在 Layout 事件里改，布局和绘制用同一个宽度）；
  选项多时 `WindowSkin.Choice(…, perRow)` 换行（界面语言六个选项三个一行）。名字尽量写短，超过 380 会被盖住。
- **字体**：沿用 IMGUI 默认字体，五种语言都能正常显示（用户录屏确认，没有方块和问号），不用借游戏的 `RDString.GetAppropiateFontForString`。
- **演示说明**（太鼓条下面那行黄字）：英文、韩文、日文比中文长得多，只占四轨面板右边的空间，放不下就缩小字号（`Painter.FitText` 靠右）。
- **README**：`README.md`（简中）、`README.zh-Hant.md`、`README.en.md`、`README.ko.md`、`README.ja.md`，开头互相链接。改 README 时几份一起改；
  国内网盘和 Q 群只写在简中、繁中两份里。设置截图各语言一张（`docs/images/settings.webp` 是简中，其他是 `settings.<代码>.webp`，
  从用户录的各语言界面里截显示页和排键页并排：窗口在 2556×1596 的录屏里是 x 810–1965、y 252–1496，各缩到 600 宽，深色底留 20 像素，总宽 1260）；
  `demo.webp` 几份共用。`docs/` 只有中文。

## 读游戏用到的接口

来自反编译 Assembly-CSharp（游戏 Unity 6000.3、UMM 0.33.3 时）。游戏大更新后先查这些还在不在：

- `ADOBase.controller / conductor / lm / isLevelSelect`
- `scrLevelMaker.listFloors`；`scrFloor.seqID / entryTime / auto / midSpin / isFake / holdLength / speed / angleLength / nextfloor`
- `scrConductor.songposition_minusi`（和 `entryTime` 同一时间轴，已扣玩家的输入校准）、`bpm`、`crotchetAtStart`、`song.pitch`
- `scrController.currentSeqID / currentState / gameworld`
- `RDString.language`（游戏当前语言，`UnityEngine.SystemLanguage`）、`RDString.AvailableLanguages`（只写进日志）

只读不改（例外：自适应游戏画幅会改摄像机的 `rect`、根画布的显示模式和 CanvasScaler 的 `dynamicPixelsPerUnit`，面板收起时都还原），没有用 Harmony 补丁。

## 几个容易踩的坑

- **只引用游戏里有的程序集**：游戏 Mono 的 System.IO.Compression 是 4.0.0.0，net48 编译会解析成 4.2.0.0，可能加载失败。Mod 现在不读压缩包，编译后检查 DLL 引用里只有 mscorlib / System / Unity 模块 / UnityModManager / Assembly-CSharp / RDTools / Newtonsoft.Json（游戏自带，读翻译表用）。
- **RDTools.dll**：`ADOBase` 的基类在这里，编译必须引用。
- **在游戏里打开网页**：不要直接用 `Application.OpenURL`。浏览器原本没开着时它会成为游戏的子进程，Steam 把游戏启动的程序也算作游戏，退出游戏后浏览器不关，Steam 一直显示「停止」（2026-11-17 实测：关掉浏览器才停）。用 `Browser.Open`：Windows 上交给 `explorer.exe` 转给系统外壳去开，只开 https 地址。
- **angleData 有 N 项就有 N+1 块砖**，按键 N 次。
- **伪双押 / 伪多押**：官方关卡用两块相隔约 25 ms 的砖表示双押，必须合成一个提示，否则会画成「双押 + 旁边多一个单押」。
  三押是三块串着来（每块隔二三十毫秒），只和第一块比时间会漏掉第三块，所以按相邻两块的转角串起来（排键规则第 11 条）。
  这个提示要等第二块砖按到才消失；第一块按到后的这 25 ms 里音符停在判定处（`OverlayFrame.TimeTo`），不然会微微越过判定线 / 判定圈，看起来像漏按（用户录屏，圆形样式和太鼓条上最明显，横条越过的那截被按键框盖住）。
- **死亡后**：`songposition_minusi` 还在走，用 `DisplayClock` 在 Fail / Fail2 状态定住画面。
- **编辑器残留的通关 / 失败状态**：编辑器播放完后 `currentState` 变成 Won，下次播放不会清掉。所以编辑器里每次开始播放时记下当时的状态，
  只有播放中状态变了才算通关 / 死亡（否则第二次播放一开始就被当成「本关结束」）。
- **暂停时收起**：关卡里 `scrController.paused` 为真时面板按出场动画收起，游戏画面和界面文字（含暂停菜单）跟着面板一起放大回全屏，不挡暂停菜单；继续后再一起滑入、缩小。
  面板完全收起时界面正好和原样重合，这时才改回覆盖模式，看不出接缝。暂停中打开本 Mod 的设置窗口时面板照常显示，方便看改设置的效果，
  界面文字（含暂停菜单）也跟着一起缩小。
- **入场 / 出场动画（`PresenceAnimator`）**：两个方向都是缓出（一开始就走得快）。原来出场是入场曲线倒着走（先慢后快），
  按 Esc 后面板在原地停约 0.2 秒才滑走，而暂停菜单已经全屏出现，看起来不连贯（录屏逐帧确认）。中途反向时从当前位置重新起一段，不跳。
- **编辑器的状态**：实测编辑器里自动播放时 `currentState` 一直是 Start（编辑器走 `scnGame.Play` → `Start_Rewind` 自己的流程），所以编辑器里以 `scnEditor.playMode` 判断是否在播放（暂停在播放中也算），不看 `currentState`。
- **自适应游戏画幅：游戏画面**（设置「自适应游戏画幅」，`Settings.ShrinkGameView`）：面板出现时按动画进度把所有 `targetTexture == null` 的摄像机的 `Camera.rect` 缩到面板让出来的区域（`GameViewport` + Core 的 `ViewportShrinker`）。
  每帧检查：摄像机当前区域不是上一帧我们设的值，说明游戏自己改了（例如编辑器暂停的黑边），就以游戏的新值为原始值，不和它抢。
  让出来的区域没有摄像机在画，会残留旧画面，所以 OnGUI 里先铺纯黑再画面板。Mod 关闭或出错时还原。
- **自适应游戏画幅：界面文字**（和游戏画面同一个开关；试验阶段曾是单独的 `ShrinkGameUi`，已合并）：「屏幕空间 - 覆盖」的画布永远铺满屏幕、挪不动，所以面板出现时把游戏和其他 Mod 的根画布临时改成「世界空间」，
  整体搬到远离场景的 `(0, -100000, 0)`，用自己的一台正交摄像机去拍，摄像机显示区域正好是让出来的区域（`GameCanvases`）。
  界面按 `s = min(区域宽/屏幕宽, 区域高/屏幕高)` 等比缩小，画布当成「区域形状、宽高各除以 s」的虚拟屏幕：字不变形，
  贴顶 / 贴底 / 铺满的元素照样贴边、铺满（只按屏幕比例等比缩再居中时，16:10 屏上下各空一条，标题、准度条离边，死亡黑幕漏边）。
  画布的 `worldCamera` 指向这台摄像机，点击也按它换算。踩过的坑：
  - 第一版改成「屏幕空间 - 摄像机」，画布尺寸变成区域大小但缩放不变，关卡上下的文字错位，已放弃。
  - 摄像机要只清深度不清颜色（`CameraClearFlags.Depth`）：世界空间的界面要做深度测试，覆盖模式不做；不清深度时缓冲里留着游戏画场景写的值，打关时的字、准度条整个不画（实测清深度后恢复）。
  - 根节点的位置不从游戏读：覆盖模式要到画画面时才摆好根节点，刚还原又马上转回去时读到的是搬远后的旧位置，再加一次偏移就跑出镜头；还原时也先把根节点摆回屏幕中心。
  - depth 每帧设成比游戏所有摄像机都大，和覆盖模式一样最后画。
  - 排序（sortingOrder）相同的画布，覆盖模式下按 Unity 的渲染顺序（`renderOrder`）决定谁在上面、谁先接点击；世界空间下改看离摄像机的远近，全在一个平面上就只剩注册顺序。用户录屏：编辑器播放中右下角的自动播放按钮（`ottoCanvas`，排序 0）点不动，同为排序 0 的还有 `tipCanvas`、`Error Meter`。现在转换时按 `renderOrder` 给每块画布排层，后画的往摄像机挪 0.05，之后新出现的排在已有的前面；面板收起时清零（用户复测按钮能点了）。界面缩着时按下鼠标，日志记一次点到的最上层元素（`点击落在「画布/对象」`），按钮点不动时对照查。
  - 世界空间下 CanvasScaler 每帧把 scaleFactor 设成 `dynamicPixelsPerUnit`（默认 1），旧式 Text 按它生成字形贴图，高分辨率屏上字会糊（实测暂停那一下字发虚）；
    转换时把 `dynamicPixelsPerUnit` 设成覆盖模式下的缩放，还原时改回原值。
  关卡里始终跟着面板缩放（暂停、开关本 Mod 设置窗口、本关结束都一样），离开关卡后面板还在滑出时也继续跟着，滑完才改回覆盖模式。
  曾经在「暂停」或「本 Mod 设置窗口开着」时直接改回覆盖模式，和面板动画对不上：关窗口那一帧界面先跳成缩小再随面板放大（录屏逐帧确认），已去掉这些例外。
  每帧找一次新出现的画布；收起时改回覆盖模式。游戏期间自己改过模式或摄像机的画布保持游戏的值。自己的挡板画布不动；IMGUI 画的字管不到。
  每种画布第一次被缩时在 UMM 日志记一行（名字、层、排序、缩放），方便对照。
- **摄像机改画贴图（0.9.0 修的花屏）**：游戏在关卡、选关里用 `scrCamera.SetupRTCam(true)` 让三个摄像机先画到一张 RenderTexture，再由 Overlaycam 整体显示；
  编辑器里又切回直接画屏幕。被缩过的摄像机切到画贴图后如果不还原，贴图里只有缩小的那块有画面，其余是没清过的显存，显示出来是一大片彩色花屏。
  现在每帧先把「缩过、现在画到贴图上」的摄像机还原（包括被禁用、手动渲染不在 `Camera.allCameras` 里的）。
- **长按**：长按砖结束那块是按住到底自动落上的，游戏里这时再按会被忽略（`scrPlanet` 里前一块是长按时直接返回，严格长按还记「太早」），所以不算一次按键；连续的长按砖合成一条（`FloorHits`）。
- **编辑器的砖块**：编辑器自己用 `scnEditor.floors`，即 `customLevel.levelMaker.listFloors`，编辑器里只读这一份。
  `ADOBase.lm`（`scrLevelMaker.instance`）按场景缓存：从主菜单直接进编辑器时它指向另一份列表，读出来一块要按的砖都没有、之后也不再变（0.9.0 前编辑器自动播放因此一直不显示）。
  其余场景先用 `ADOBase.lm`，取不到再用 `customLevel.levelMaker`；判断对象是否已销毁要用 Unity 的 `==`，`?.` 判断不了。
  关卡指纹里含砖块列表本身（`RuntimeHelpers.GetHashCode`），换了一份列表就会重排。一块要按的砖都没有时不显示，并在日志里写出各类砖（已销毁 / 自动 / 中旋 / 假砖 / 长按）的数量。
  不再要求 `controller.gameworld`（自由移动段会被设成 false）。选关界面（`isLevelSelect`、`isCLS`）不显示。
- **netstandard 2.1**：Unity 6 的模块按 netstandard 2.1 编译，要引用游戏目录里的 `netstandard.dll`。
- **AudioClip.SetData**：Unity 6 有 `ReadOnlySpan` 重载，net48 编译环境没有这个类型，嗒声改用读取回调生成。

## 日志

用 UMM 自带的 Logger（分 Log / Warning / Error），写进 `Managed\UnityModManager\Log.txt`，每次启动游戏重写。日志一律是中文（给开发者看），不跟界面语言走。
每次排键会记一行状态（按键次数、提示数、双押数、各轨使用次数）；画面显示 / 隐藏切换时记一行原因（例如「画面：隐藏（游戏状态 Start）」），查「为什么没显示」先看这里。
运行中出现意外异常会记完整堆栈并停用叠加层，避免每帧刷日志。
